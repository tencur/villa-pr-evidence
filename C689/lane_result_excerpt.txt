# extract_surface_tracks open_predictions: lane notes (excerpt, 2026-11-07)

### extract_surface_tracks.py crashes before reading anything, because `vesuvius.data.utils` no longer exists (HIGH)
- **Where:** `spiral-fitting/extract_surface_tracks.py:open_predictions` on 7e6b82164. It does `from vesuvius.data.utils import open_zarr`, but #2440 (baf5e605b, merged 2026-11-04) deleted `vesuvius/src/vesuvius/data/utils.py`. This is the only remaining importer of that module in the repo outside `deprecated/` (checked with git grep on origin/main).
- **Who hits it:** every `extract_surface_tracks.py --backend cpu` run, and every `--backend auto` run without a usable GPU. That covers all CPU track extraction for spiral fitting, including the new `--slab-workers` path from #2221. The GPU backend also goes through `open_predictions` for remote URLs and for local zarrs with '.' keys or other layouts its direct reader rejects (`surface_tracks_gpu._open_input`). Every CPU test replaces `open_predictions` with an in-memory array or `zarr.open_array`, so the suite never noticed.
- **Repro on main:** synthetic predictions (`scripts/make_preds.py` writes 96x704x704 uint8 rings). Then:
  `cd wt/spiral-fitting && PYTHONPATH=/home/pi/fixwork/r3s/vcr_py venv-z321/bin/python extract_surface_tracks.py --backend cpu --predictions /home/pi/fixwork/h11Z3/preds.zarr --out main.dbm --z-min 0 --z-max 96 --no-packed-store`
  gives `ModuleNotFoundError: No module named 'vesuvius.data.utils'` (extract_surface_tracks.py:83) and exit 1.
- **Fix:** branch `fix/spiral-tracks-open-predictions-vc-reader` (first built as 09ee23ca0; the PR head cda35ee6f only moves the new test up the file). `open_predictions` now uses `vc_reader.reader.open_zarr(path)`; spiral-fitting already depends on vc-reader since #2221. Source change +3/-6; one new test, +27.
- **Test:** `tests/test_extract_surface_tracks.py::test_cpu_backend_opens_a_real_zarr` writes `synthetic_predictions()` to a zarr on disk, runs `run_cpu` on that path and compares the DBM with a run on the in-memory array. Main: FAILED (ModuleNotFoundError). Fix: passed. `test_extract_surface_tracks.py` and `test_cc_labels.py` with the fix: 40 passed, 1 skipped (GPU).
- **End-to-end with the fix:** the CLI above exits 0 and writes 28 keys with 89 tracks. `--slab-workers 3 --kimimaro-parallel 1` writes the same tracks under every key as `--slab-workers 1` (the order of tracks inside a key can differ; two `--slab-workers 1` runs differ in order too, from Kimimaro's own parallelism). So the #2221 forked workers also work with a vc_reader-opened array, which no upstream test covered: its fork test uses `zarr.open_array`.
